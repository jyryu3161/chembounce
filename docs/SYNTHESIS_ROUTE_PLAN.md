# 합성 경로 우선 개발 계획 (2026-10-23)

**상태: P1 명시적 opt-in 구현 검토 중, 고정 예산 비교 전.** 아래 작업의 효능은 아직 입증되지 않았다. 현재 `--recommend`/`recommend()`의 기본값은 `qualified-selective-engineering-v7`이며, v7은 v5의 경로·근거 할당(`inherit-v1`)을 계승한다. v6의 변경된 할당은 명시적으로 선택하는 과거 프로필일 뿐 기본값이 아니다. 현재의 구조, 입체화학, 원래 입력에 대한 유사도, 전체 경로 재생, 계산 근거, 3D 및 최종 qualification 관문은 그대로 유지한다.

## 출발점과 해석 범위

[추적되는 고정 12입력 경로 기준선](../benchmarks/results/synthesis-route-development-20261023/baseline.json)은 공개 개발 입력 12개(6표적)의 재사용 결과다. 12개 모두 실행을 완료했지만 qualified 결과는 0개였다. 저장된 기록에는 경로 683건, 계산적으로 지지된 경로 기록 304건(12입력 중 5개), 입력별로 중복 제거한 지지 생성물 69쌍이 있다. 이 수치는 동일 구조의 반복 경로를 포함하는 기록 수와 고유 생성물을 혼동해서는 안 된다. 각 생성물의 **첫 번째** 지지 경로만 보면 67개는 1단계, 2개는 2단계이며, 그 첫 경로의 정확한 최종 생성물은 해당 모델이 적어 낸 목표 생성물과 일치하지 않았다. 대체 경로 전체에 대한 결론은 아니다. 상세 실행 계획과 원본 경로·분석 자료는 Git에서 제외된 로컬 `benchmark-results/qualified-development-20261023/`에 있으며, 위 기준선에 파일 SHA-256을 고정했다.

저장된 3D 점수 계산 시도/기록은 39건(전역 고유 생성물 수라는 뜻은 아님)이고 screening 통과는 0개였다. 설계 41건은 지정되지 않은 입체화학 때문에 제외됐다. 전방 예측 호출 예산 소진으로 평가하지 못한 경로 기록 194건은 화학적 실패로 세지 않는다. 입력 대 최종 생성물의 비교에는 같은 지문 정의를 써야 한다. native 설계 표의 유사도(sparse Morgan **count**, radius 2)와 최종 qualification의 bit 지문 유사도를 직접 연결한 감소율은 계산하지 않는다. 이 기준선은 저장된 생산자 기록의 기술 통계이며 독립적인 합성 검증, 생물학적 효능 또는 홀드아웃 성능이 아니다.

## 구현 순서

| 순서 | 작업과 코드 접점 | 완료 조건과 선행 관계 |
|---|---|---|
| P0: 경로 단위 기준선 | `chembounce_synthesis/workflow.py`, `routes.py`, `evidence_outcomes.py`의 기존 저장 필드를 사용해 각 입력→정확한 생성물→경로 ID→단계별 검증/전방 결과→예산 상태를 구분해 보고한다. 심사 가능한 후보 목록은 `results.json`의 qualified 반환과 별도 파일/표기로 둔다. | 0/미평가/실패를 분리하고 경로·생성물 중복을 제거할 수 있어야 한다. 저장된 raw proposal, 카탈로그·규칙 해시, 결정 이유를 추적할 수 있어야 한다. 이 단계의 진단 목록은 사용자에게 qualified 추천으로 표시하지 않는다. |
| P1: 실제 경로에서 후보 만들기 | `reactions.py`의 실제 반응 규칙과 `catalog.py`의 구체적 building block을 입력으로, `routes.py`에 **한 단계 우선, 최대 두 단계까지** 제한된 경로 유도 탐색을 추가한다. 기존 반응성 호환성/가까운 building block 색인으로 조합 전 후보를 줄이고 명시적 beam·조합·단계·시간 상한을 적용한다. 전체 분자 생성물을 규칙으로 재생한 뒤 원 입력의 지정된 주변 anchor/특징과 보존되는 원자의 mapped stereo를 확인한다. 치환으로 CIP R/S 표기가 달라질 수 있으므로 문자열의 R/S만 비교하지 않으며 새 불명확 입체중심은 임의로 정하지 않고 제외한다. 원래 scaffold 전체를 고정하지 않는다. 완전한 구체 경로를 얻으면 `workflow.py`의 intake에 넘겨 중복 LLM 제안을 하지 않는다. 모델의 목표 구조 문자열은 검증된 생성물을 대신하지 못한다. | P0 및 알려진 양성/음성 반응 fixture가 선행한다. 동일 catalog/rule snapshot에서 생성한 경로가 `verify_route`, 전체 atom/stereo audit, 정확한 생성물 일치와 기존 설계/최종 제품 관문을 통과해야 한다. 전역 catalog×rule 열거는 하지 않는다. 새 생성 정책은 명시적 opt-in 프로필/설정과 source binding을 갖고 v7 기본값을 조용히 바꾸지 않는다. 이 작업이 가장 가까운 실제 화학 개선이다. |
| P2: 다단계 연결과 근거 예산 | `routes.py`의 DAG 재생/확장(`expand_route`)과 `workflow.py`의 기존 경로 검색·전방 예측 캐시와 이유별 구분을 활용해, 앞 단계 생성물에 의존하는 다음 단계의 frontier를 관리한다. 현재의 생성물/설계별 첫 경로 배분을 보존하며, v6의 별도 family/design 순환 배분은 기본값으로 취급하지 않는다. 반복 호출 합치기는 준비된 반응물·시약과 예측기 출처까지 포함하는 기존 안전한 cache key에 한정하고, 경로/맥락별 audit는 따로 유지한다. 미평가 경로와 이미 지지된 경로 사이의 예산 배분을 명시한다. | P1의 1–2단계 경로가 먼저 정확히 재생돼야 한다. 연결되지 않은 단계, 중간체가 다른 경로, 순환, 예산 중단을 음성/미평가 fixture로 분리한다. 예산 배분 변경은 새 프로필/명시적 설정과 출처로 기록하고 v7 기본 정책을 조용히 바꾸지 않는다. |
| P3: 실험 맥락 | 기존 `reaction_records.py`의 공개 ORD 기록 처리와 `catalog.py`/`route_audit.py`의 leaf 출처를 재사용해, 확인 가능한 반응 조건, 공급사 SKU·재고 시점, 보호기/선택성 등의 근거를 별도 필드로 연결한다. | 출처 URL/식별자·조회일·구조/반응 대응이 없는 항목은 `unknown`이다. 현재 카탈로그 등재와 계산 예측을 구매 가능성, 수율 또는 실험 합성 가능성으로 승격하지 않는다. 외부 자료가 확보되기 전에는 이 단계가 P1/P2의 계산 경로 관문을 대체하지 않는다. |

P1은 기존 모델이 그럴듯한 반응 문장을 내길 기다리는 대신, 실제 카탈로그 잎과 규칙 적용으로 **재생 가능한 최종 구조**를 먼저 만든다. 그 뒤 원래 hit의 필요한 약리 특징/anchor와 명시된 stereo를 유지할 수 있는지만 판단한다. 넓은 무제한 열거는 하지 않는다. 전방 예측은 각 단계의 제한된 계산 근거이고, `catalog_and_rule_verified`는 규칙/카탈로그 일치일 뿐 실험 성공이 아니다. P2에서 다단계를 늘려도 모든 의존 단계가 확인돼야만 전체 경로를 지지된 것으로 부른다.

## 제안하는 검증 게이트 (관측 성과 목표가 아님)

1. **작은 화학 fixture 먼저:** 카탈로그와 규칙으로 직접 만든 알려진 양성 1단계·2단계 경로, 결합 위치가 다른 음성, 누락 중간체, 잘못된 생성물, 불명확/반전된 입체화학, 서로 다른 catalog ID·중복 경로를 포함한다. `verify_route`와 전체 경로 audit의 결과, 저장/재생 결과가 일치해야 한다. 임의의 SMILES 수선, 부분 경로 승인, 실패 후 조용한 재시도는 허용하지 않는다.
2. **동일 비용의 쌍 비교:** fixture 통과 후에만 같은 12개 개발 입력, native/provider seed 42와 최종 refinement 42/43/44, 고정 asset/hash, 입력당 960초, 동일 GPU 기종·스레드 한도 및 현재 3D/qualification 임계값으로 기존 v7과 새 명시적 설정을 나란히 실행한다. 실행 전 후보·분기·경로·모델 호출·토큰·생성물 상한과 GPU/CPU 배치, 자산 로딩을 포함한 시간/자원 청구 방식을 함께 동결한다. 모델·규칙·카탈로그 변경이 있으면 별도 요인으로 기록한다. 한 입력의 시간초과/오류는 0개로 대입하지 않는다. 변경 후 새 12회 실행은 새 폴더에 보존한다.
3. **계량 단위:** 입력별 검증 경로 보유율, 지지된 **고유 정확 생성물** 수, 모든 단계가 audit·전방 예측을 마친 전체 경로 수, 1/2/다단계 분포, 예산 미평가율과 단계별 이유, proposal→검증 경로→3D screening→refinement→qualified 반환의 각 분모를 함께 보고한다. 입력과 재생 최종 생성물의 유사도/보존 특성은 동일 지문·동일 구조 정의로 다시 계산한다. 중복 경로 수 증가는 성공 지표가 아니다.
4. **채택 조건:** 알려진 양성 경로가 재생되고 음성·stereo fixture는 거절될 것, 기존 최종 관문이 약해지지 않을 것. 큰 비교 실행 전에 주 지표를 **지지 경로가 있는 입력 수** 또는 **완전 감사된 고유 입력/정확 생성물 쌍 수**로 지정하고, 고정 총 상한 안에서 기준선보다 증가해야 경로 개선으로 채택한다. 다른 지표의 감소, 미평가·실패·비용 증가는 함께 보고한다. 최종 qualified 수는 별도 결과로 남긴다. 3D에서 다시 탈락하면 경로 개선을 qualified 성공으로 부르지 않는다. 개발 패널의 개선은 후속 독립 입력 검증 전까지 일반화하지 않는다.

현재 P1 구현안은 명시적 `route_first` 설정에서 실제 catalog+rule 후보를 1단계 우선·최대 2단계까지 생성하고, 완전한 경로를 기존 intake와 전방 근거·3D·qualification 단계로 넘긴다. 후보와 최종 추천은 별도 파일에 기록한다. 국소 입체 anchor의 대응이 불명확하거나 바뀌면 보수적으로 제외하며, 전역 원자 대응을 추정하지 않는다. 이 구현안의 채택 여부는 위 고정 예산 비교와 원래 관문의 유지 여부를 검토한 뒤 결정한다. P2의 일반 다단계 frontier/예산 정책은 별도 변경이다.
