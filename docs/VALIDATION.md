# Validation record and publication scope

This file distinguishes verified software behavior from scientific conclusions.
A software repair and a faster similarity kernel do not, on their own, establish
superior scaffold-hopping chemistry or suitability for a particular journal.

## Legacy ADP defect

`benchmarks/legacy_adp.json` was generated by executing the tagged 1.0 source in a
temporary directory, with only `RDBASE` supplied to let pip-installed RDKit import.
The exact reported ADP produces three automatic scaffolds: both purine-containing
scaffolds fail with `AtomKekulizeException`, and the ribose scaffold fails with an
`EditableMol.ReplaceAtom(None, ...)` argument error. The 1.0 screening loop catches
these exceptions and continues, explaining a header-only final table regardless
of available replacement candidates. ADP also violates donor/acceptor filters;
that is a separate issue, not the cause of the attachment exceptions.

Reproduction (requires 1.0 dependencies including MolVS and PubChemPy):

```bash
python benchmarks/reproduce_legacy_adp.py
```

The 2.0 regression suite uses the exact supplied SMILES and asserts valid connected
products for all three scaffold families. It tests that retained ribose stereo and
phosphates survive purine replacement, and that same-scaffold reconstruction can
recover inputs with stereocenters, isotopes, double bonds and bridged remnants.

## Automated checks

Run `pytest` and `ruff check .`. The suite tests real attachment, descriptor and
search calculations, plus CLI exit/status behavior. It includes property rejection,
core preservation in products, finite parameter validation, hard candidate limits,
output protection, custom-library precedence, database switching and source hashes,
small-database fingerprint verification, seeded 3D repeatability, and CATS fixes.
The ODDT reference-comparison test is optional and runs when that legacy dependency
is installed; the production implementation does not require it.

Two local environments were used: Python 3.10.12 with RDKit 2025.09.6 / NumPy 1.26.4,
and a clean installation with RDKit 2026.9.1 / NumPy 2.2.6. The clean environment's
complete dependency snapshot is `requirements-lock.txt`. Package installation,
`pip check`, wheel building, CLI entrypoint, shell syntax and notebook code-cell
syntax are checked locally. The GitHub Actions matrix targets Python 3.10–3.12;
remote CI status and interactive Colab execution are not inferred from local tests.

## Search-kernel benchmark

```bash
python benchmarks/benchmark_search.py --rows 100000 --repeats 5
```

`benchmarks/search_100k.json` stores all repetitions, platform and dependency
versions. Two separate workers search the same seeded synthetic sparse bits.
Input construction and loading are excluded from elapsed search times. The legacy
worker uses full AND/OR matrices and a global sort; the packed worker uses chunks
and bounded top-k selection. Equal-score ordering is normalized to row index to
compare outputs. All top-100 indices and scores must match exactly.

The recorded run obtained 0.3764 s versus 0.1677 s median (2.24×), fingerprint arrays
of 204.8 MB versus 25.6 MB, and sampled worker RSS of 527.9 versus 161.9 MiB. RSS is
sampled every 2 ms and includes worker imports/input arrays. Earlier-process high
watermarks are deliberately not used. These figures do not establish full-workflow
speedup, scaling across hardware, or molecular-quality improvement.

## Whole-workflow evaluation

`benchmarks/molecules.json` is a small hand-selected engineering stress panel:
ADP, the original README example, an aromatic ether, a chiral sidechain, fused rings,
a macrocycle and an acyclic control. It is not a statistically representative
chemical benchmark. To evaluate on the published library:

```bash
python benchmarks/benchmark_workflow.py \
  --fingerprint-db data/fingerprints_mw250_v2 \
  --output benchmark-results/published-mw250
```

Use the full database as a separate experimental condition. Keep all individual
manifests, summaries, generated candidates and resource reports. The script checks
sanitization/connectivity, uniqueness, caps and similarity thresholds and records
zero-result inputs rather than dropping them from the denominator.

## Evidence still required for a journal manuscript

The repository now supports reproducible software experiments. A claim of novel or
superior chemistry additionally needs a defined scientific question and empirical
evidence. Before manuscript submission:

1. Establish a licensed, versioned multi-class evaluation set and preregistered
   inclusion criteria; control overlap with the scaffold library and known actives.
2. Compare against appropriate scaffold-hopping baselines under matched libraries,
   compute budgets and output counts. Include per-input failures and confidence
   intervals, not only aggregate successful cases.
3. Measure diversity, scaffold novelty, preserved pharmacophores and chemical
   plausibility. Include controlled beam-width, similarity, library-size, filter,
   stereochemistry and conformer-seed ablations.
4. Obtain chemistry review and task-appropriate activity/synthesis evidence for
   selected candidates. Similarity, QED and SA are not substitutes for those data.
5. Resolve project and third-party licensing, freeze a release and data artifacts,
   archive an executable environment and deposit the exact experiment outputs.

These are manuscript-level requirements, not claims that this patch has already
completed comparative or experimental validation. The 2.0 branch remains a
publicly identifiable development version until release criteria are satisfied.
